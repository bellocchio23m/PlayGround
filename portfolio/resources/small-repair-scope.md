# Scope one paid workflow repair without an open-ended rebuild

A useful small engagement names the blocked action and its completion condition. Start with a workflow such as “create a request and see it after reload,” then identify the repository area involved.

A written scope can contain these six decisions.

| Decision | What to agree |
| --- | --- |
| Defect | One reproducible failure and affected view |
| Delivery | Patch or pull request and a short handover |
| Evidence | Before/after reproduction and relevant checks |
| Review | Named acceptance conditions and one correction round |
| Timing | Deadline after source and access review |
| Cost | Final currency, total and payment arrangement |

State any dependencies that can affect the estimate, including unavailable source, an external API or a required backend change. If discovery reveals a different problem, revise the scope in writing before expanding work.
